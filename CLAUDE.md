# DinoPunk

Browser 2D action-platformer. Taro, a scientist from cyberpunk 2077, is stranded
in the Cretaceous and must gather relics to power his portal remote home.
Single player, saves locally, no backend.

Full plan: `~/.claude/plans/i-m-going-to-create-fluttering-hammock.md`

## Commands

```bash
npm run dev        # vite dev server on :5173
npm test           # vitest over the pure model + anim code
npm run typecheck  # tsc -b --noEmit
npm run lint       # eslint, including the model purity rule
npm run build      # tsc -b && vite build
```

Dev-only rig workbench: <http://localhost:5173/#/rig>

In dev, `window.dinopunk` is the live `GameLoop`, so the running simulation can
be inspected and driven from the console.

Content is generated by authoring scripts, not hand-edited JSON:

```bash
node tools/authorClips.mjs      # Taro's 14 clips
node tools/authorDinoClips.mjs  # the mini dinosaur's 6
node tools/authorLevels.mjs     # cave_01.json (opens in Tiled)
```

## Architecture

MVC, enforced rather than aspirational.

- `src/model/` — **pure**. All game state and rules, deterministic, fixed 60Hz.
  Receives intents, not keycodes. An ESLint rule rejects any import of React,
  Pixi, Zustand, Howler, idb-keyval, or the outer layers, plus direct use of
  `window`/`document`/`localStorage`. **If that rule fails, fix the import, not
  the rule** — model purity is what makes combat testable without a canvas.
- `src/anim/` — pure animation runtime (compile, sample, blend, simulate).
  Shared by model and view; imports nothing but itself.
- `src/data/` — pure JSON content: rigs, clips, levels, dialogue.
- `src/view/pixi/` — renders a solved pose. `src/view/react/` — all UI.
- `src/controller/` — input → intents, game state machine, commands.
- `src/bridge/` — Zustand projection of the model for React.

### The performance rule

React must never re-render at 60fps. Per-frame values (HP, blood, gold) go into
a narrow store slice only the relevant HUD components subscribe to. Everything
else syncs on domain events. Entity positions go straight to Pixi and never
enter React at all.

## State of play

**Phase 0 (animation foundation) and Phase 1 (vertical slice) are complete.**
Playable end to end: menu -> intro cutscene -> cave -> platforming -> first
dinosaur -> bag and crafting -> save/load -> cave mouth.

Not yet built: the jungle and later biomes, the shop NPC, audio, the tutorial
prompt sequence, the boss, and rebindable keys. Reaching the cave mouth ends
the slice with a victory screen rather than pretending `jungle_01` exists.

## Rig conventions

These are easy to get wrong and expensive to debug. Read before touching
`src/data/rigs/` or `src/data/clips/`.

- **Angles in JSON are DEGREES.** The compiler converts to radians once.
- **Space:** origin at the character's ground contact point, +X right, **+Y
  down**. Gravity is a positive Y value.
- **A bone's local +X axis points along the bone.** So rest `-90` points up,
  `+90` points down, `180` is reversed from the parent.
- **Track values are absolute local rotations**, not deltas. Read them against
  the rest pose:

  | bone | rest | meaning |
  |---|---|---|
  | `thigh*` | 180 | lower swings the leg **forward**, higher swings it back |
  | `shin*` | 0 | positive bends the knee (backward, as knees do) |
  | `armUpper*` | 180 | lower swings the arm **forward** |
  | `armLower*` | 0 | **negative** flexes the elbow forward |
  | `foot*` | -90 | positive points the toe down |
  | `torso` | 0 | positive leans forward |
  | `head` | 0 | positive looks down |

- **Draw order is `z`, independent of the bone hierarchy.** `RigView` lays bones
  out flat and sorts by `z` precisely because Pixi always draws a child after
  its parent — which would force the back arm (a child of the chest) to draw in
  front of the torso.
- **Clip `events` drive gameplay.** Combat reads `hitboxOn`/`hitboxOff` from the
  clip, so active frames and visuals cannot drift apart. Never hardcode an
  attack's active window in the combat system.
- Chain bones (coat, hair, tails) are simulated, not authored. Their pose is
  overwritten by `ProceduralMotion`, so authoring rotation tracks on them does
  nothing.

## Art pipeline

Comic art throughout, **no pixel art** — pixel sprites beside a comic-shaded
Taro read as unfinished.

Characters are cut-out skeletal rigs animated by hand-authored keyframe data,
**not** drawn frames. Image models cannot produce frame-consistent animation, so
Nano Banana only ever generates stills: one flat, non-overlapping **part sheet**
per character (on magenta `#FF00FF`, keyed out with ImageMagick), plus cutscene
panels, parallax layers, props, and icons.

Every rig is built and tuned with placeholder shapes first. Real art is a
texture swap with zero animation rework, so animation is never blocked on art.

Environments decouple collision from visuals: Tiled object layers give exact
collision, painted parallax + 9-slice platform skins give the look.

UI is React + CSS (thick keylines, flat fills, halftone, hard offset shadows),
not an asset pack, so restyling is a variable change.

## Things that bit, and should not bite twice

- **Ground friction must not exceed ground acceleration.** It did, and Taro
  could not walk at all. Drag now only applies when he is not driving.
- **Attack hitboxes must reach low.** Authored at chest height, punches could
  not touch a 62-unit-tall mini dino at all. They now span shin to head.
- **Interpolation snapshots per simulation tick, not per rendered frame.**
  `GameLoop` calls `renderer.snapshot()` before each `game.step`. Doing it per
  frame makes sprites lag badly whenever ticks and frames disagree.
- **Pixi 8's `renderer.width/height` are already CSS pixels.** Dividing by
  `resolution` halves the viewport the camera reasons about. Use `app.screen`.
- **Levels are `.json`, not `.tmj`**, so `resolveJsonModule` can import them.
  Tiled opens them either way.
- A level-design test asserts every ledge is within one jump of the last; the
  first cave layout walled Taro in at the spawn and that test now catches it.
